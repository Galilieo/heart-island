# 07 API 设计规则

## 命名

- 路径按业务模块组织，如 `/mood/*`、`/community/post/*`、`/admin/*`。
- 新模块先保持清晰，不为了“REST 完美”破坏现有风格。
- 管理端接口统一放在 `/admin/` 下。

## 请求与返回

- 请求对象用 DTO，不直接暴露 Entity。
- 返回对象用 VO，不把数据库字段完整透出。
- 返回结构继续沿用项目里的统一结果对象。
- 分页接口要明确 `pageNum`、`pageSize`、筛选条件、排序规则。

## 权限

- 当前用户身份从 JWT 获取，不相信前端传入的 `userId`。
- 普通用户只能访问自己的心情、记忆、报告、会话。
- 社区匿名展示不等于后端无身份。
- 后台接口必须校验管理员权限。

## 错误处理

- 参数错误要给出明确提示。
- 未登录、无权限、资源不存在、资源不属于当前用户要区分。
- AI API 调用失败时，要记录失败原因，并设计降级返回。

## 接口设计输出格式

```text
接口名：
方法和路径：
权限：
请求参数：
返回字段：
业务规则：
异常情况：
自测方式：
```

## 兼容性

- 改已有接口前先说明是否影响前端现有调用。
- 能新增字段解决的，不轻易改变旧字段含义。
- 删除或重命名接口必须等用户明确确认。
