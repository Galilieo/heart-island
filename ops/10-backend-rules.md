# 10 后端开发规则

## 分层规则

- Controller：接收请求、做基础校验、调用 Service、返回结果。
- Service：业务规则、权限判断、事务、AI 调用编排。
- Mapper：数据访问，不塞业务判断。
- DTO：前端请求入参。
- VO：返回前端的数据结构。
- Entity：数据库表映射，不直接作为接口契约。

## 用户身份

- 当前用户从 JWT 或拦截器上下文获取。
- 新增、修改、删除个人数据时，后端必须校验资源归属。
- 不允许让前端传 `userId` 决定数据归属。

## AI 调用

- AI 调用要有超时、失败记录、兜底策略。
- prompt 构造尽量集中，避免散落在 Controller。
- 保存 AI 调用记录时要包含业务类型、业务 id、状态、错误信息。
- 后续多轮对话、RAG、工具调用要能复用记录链路。

## 数据库访问

- 简单 CRUD 可用 MyBatis-Plus。
- 复杂查询要说明查询条件、排序、分页和索引依据。
- 更新和删除前要确认资源存在且属于当前用户。

## 异常与返回

- 参数错误、未登录、无权限、资源不存在要区分。
- 不把 Java 异常堆栈直接返回前端。
- 关键失败要记录日志，方便复盘。

## 自测重点

- `mvn test`。
- 登录后访问接口。
- 未登录访问受保护接口。
- 越权访问他人资源。
- AI API 失败或超时时的业务表现。
