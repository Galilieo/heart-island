# 02 Agent 工作流程

## 默认流程

1. 读取 `AGENTS.md` 和任务相关的 `ops/` 文档。
2. 明确任务类型：新功能、接口设计、数据库设计、联调、bugfix、复盘、只读分析。
3. 只读分析现有源码、SQL、配置和文档。
4. 输出方案：目标、影响范围、涉及文件、接口、表结构、自测方式、风险。
5. 等待用户确认后再改业务代码，除非用户明确说“直接改”。
6. 修改后执行必要自测，并说明通过项、未测项和原因。
7. 需要沉淀时，把过程写入 `AI_WORKLOG/`。

## 新功能必须先回答

- 这个功能解决什么用户场景？
- 是否影响已有登录、心情、社区、后台、AI 调用链路？
- 前端要改哪些页面、组件、API、store？
- 后端要改哪些 Controller、Service、DTO、VO、Entity、Mapper？
- 是否需要新表、字段、索引、唯一约束？
- API 如何命名，权限如何控制，错误如何返回？
- 怎么自测，怎么验收？

## Bugfix 流程

1. 先复现或定位现象。
2. 找到最小影响范围。
3. 说明根因和修复点。
4. 等确认后修改。
5. 做回归验证，避免只修一个表面现象。

## 输出要求

- 用中文为主。
- 结论先行，文件路径要具体。
- 不确定的地方标注“待确认”。
- 不输出敏感部署信息、账号、密钥。
