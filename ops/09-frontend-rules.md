# 09 前端开发规则

## 目录约定

- 页面放在 `xinyu-vue/src/views/`。
- 可复用组件放在 `xinyu-vue/src/components/`。
- 接口封装放在 `xinyu-vue/src/api/`。
- 跨页面状态放在 `xinyu-vue/src/stores/`。
- 请求拦截和 token 逻辑走 `xinyu-vue/src/utils/request.js`。
- 样式优先复用 `src/styles/` 里的全局规则。

## 新功能接入顺序

1. 先确定页面入口和路由。
2. 设计 API 调用函数。
3. 判断是否需要 Pinia store。
4. 拆页面组件和状态。
5. 补加载、空状态、错误提示、权限跳转。
6. 执行 `npm run build` 或必要的页面自测。

## 交互要求

- 表单要有提交中状态，避免重复提交。
- 列表要有加载、空状态、失败提示。
- 需要登录的页面要处理未登录情况。
- AI 生成类功能要显示生成中、失败兜底和重试入口。
- 移动端不要让按钮、输入框、文字挤在一起。

## 风格要求

- 优先复用项目已有基础组件。
- 不擅自引入新的 UI 库。
- 不把大段业务逻辑塞进模板。
- API 字段转换尽量集中在接口层或明确的适配函数中。

## 自测重点

- 登录态刷新后是否正常。
- 接口错误时页面是否有提示。
- 空数据是否好看且不报错。
- 移动端宽度下是否能正常操作。
- 管理端和用户端入口是否互不影响。
