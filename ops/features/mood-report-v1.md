# 情绪周报模块 v1

状态：初版规划，未实现。

## 功能目标

基于用户一周内的心情记录生成情绪周报，展示情绪趋势、关键词、主要压力来源、积极事件和温和建议。

## 用户场景

- 用户想回顾这一周情绪变化。
- 用户希望 AI 总结自己常见压力和改善建议。
- 用户希望保存历史周报，方便复盘。

## 业务流程

1. 用户进入周报页面。
2. 前端请求本周或指定周的周报。
3. 后端汇总该用户一周心情记录。
4. 如果已有周报，直接返回。
5. 如果没有，生成统计摘要并调用 AI 生成文字报告。
6. 保存周报并返回前端。

## 前端改动

- 新增情绪周报页面。
- 支持选择周范围。
- 展示趋势、摘要、AI 建议、生成时间。
- 处理无记录、生成中、生成失败。

## 后端改动

- 新增周报 Controller、Service、DTO、VO、Mapper。
- 汇总心情记录。
- 调用 AI 生成报告。
- 支持重新生成，需用户确认。

## 数据库改动

- `mood_report`：周报表。
- 字段建议：`user_id`、`start_date`、`end_date`、`summary`、`ai_content`、`status`。
- 唯一约束：`user_id + start_date + end_date`。

## API 设计

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| GET | `/mood/report/week` | 登录用户 | 获取指定周报 |
| POST | `/mood/report/week/generate` | 登录用户 | 生成周报 |
| POST | `/mood/report/week/regenerate` | 登录用户 | 重新生成周报 |

## 权限与安全

- 只能查看自己的周报。
- 周报包含隐私内容，不进入社区公开数据。
- AI 生成内容要避免医疗诊断语气。

## 异常处理

- 本周无心情记录：返回空状态和引导，不调用 AI。
- AI 失败：保存失败状态，允许重试。
- 重复生成：默认返回已有报告，除非调用重新生成接口。

## 验收标准

- 有记录时能生成周报。
- 无记录时页面展示空状态。
- 同一周重复打开不会重复生成。
- 用户不能访问他人的周报。
