# 06 新功能开发规则

## 开发前必须有方案

每个新功能先输出以下内容，等用户确认后再改代码：

- 功能目标。
- 用户场景。
- 业务流程。
- 影响范围。
- 涉及文件。
- 前端改动。
- 后端改动。
- 数据库改动。
- API 设计。
- 权限与安全。
- 异常处理。
- 验收标准。
- 自测清单。

## 推荐顺序

1. 先写或补 `ops/features/功能名.md`。
2. 明确接口和表结构。
3. 后端先完成 DTO、VO、Controller、Service、Mapper。
4. 前端再接 API、store、页面、组件。
5. 最后做主链路自测和回归测试。

## 影响范围判断

- 是否影响登录态或权限？
- 是否影响心情记录主链路？
- 是否影响 AI 调用记录？
- 是否影响社区内容展示？
- 是否需要后台管理入口？
- 是否需要新增索引、唯一约束、状态字段？

## 验收表达

验收标准要能被测试，不写“体验更好”这种空泛描述。建议写成：

- 给定某个用户状态。
- 当用户执行某个操作。
- 那么页面、接口、数据库或日志出现可验证结果。

## 暂缓项

规划中但本轮不做的内容，要放到“后续迭代”，不要混进本轮验收标准。
