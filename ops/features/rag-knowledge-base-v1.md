# RAG 知识库模块 v1

状态：初版规划，未实现。

## 功能目标

为 AI 回复提供可维护的知识来源。v1 先支持后台录入或导入短文本知识，AI 回复前检索相关知识片段，再生成更稳定的回答。

## 用户场景

- 管理员维护心理健康常见问答和平台规则。
- 用户提问时，AI 能参考知识库给出更一致的回答。
- 后台可停用过期或不合适的知识。

## 业务流程

1. 管理员新增知识条目。
2. 系统保存标题、内容、分类、状态。
3. 用户触发 AI 回复。
4. 后端根据用户输入检索相关知识。
5. prompt 中加入检索结果。
6. AI 生成回复并记录引用摘要。

## 前端改动

- 后台新增知识库管理页。
- 支持列表、搜索、分类筛选、新增、编辑、启用停用。
- 用户端 v1 可不展示引用，先保证回复质量。

## 后端改动

- 新增知识库 Controller、Service、DTO、VO、Mapper。
- 新增检索服务。
- AI prompt 构造处接入检索结果。
- 后台接口需要管理员权限。

## 数据库改动

- `rag_knowledge`：知识条目表。
- 字段建议：`title`、`content`、`category`、`tags`、`status`、`create_time`、`update_time`。
- v1 可先用 MySQL like 或关键词匹配，后续再接向量库。

## API 设计

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| GET | `/admin/rag/knowledge/page` | 管理员 | 知识分页 |
| POST | `/admin/rag/knowledge` | 管理员 | 新增知识 |
| PUT | `/admin/rag/knowledge/{id}` | 管理员 | 编辑知识 |
| PUT | `/admin/rag/knowledge/{id}/status` | 管理员 | 启用或停用 |

## 权限与安全

- 知识库后台只允许管理员维护。
- 不把用户隐私写入公共知识库。
- 心理建议要避免诊断和绝对化措辞。

## 异常处理

- 无检索结果：AI 走普通回复。
- 知识过长：截断或限制条数。
- 知识停用：不参与检索。

## 验收标准

- 管理员能维护知识条目。
- 停用知识不参与 AI prompt。
- 有相关知识时，AI prompt 包含知识摘要。
- 普通用户不能访问后台知识接口。
