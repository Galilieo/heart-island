# 轻量长期记忆模块 v1

> 2026-11-07分期对齐提示：本功能对应总方案的阶段5可管理记忆。请先读[整体分阶段设计](../../../ops/features/xinyu-upgrade-master-plan.md)。本文件保留为未实施的初稿，具体接口、数据归属与验收需按确认后的总方案修订；总方案目前也待用户评审。

状态：初版规划，未实现。

## 功能目标

从用户授权的心情记录和对话中提炼轻量记忆，用于让 AI 回复更贴合用户长期状态。v1 只保存简短摘要和标签，不保存过度敏感推断。

## 用户场景

- 用户希望 AI 记住自己常见压力来源。
- 用户希望 AI 以后用更适合自己的方式回复。
- 用户需要查看、删除或关闭记忆。

## 业务流程

1. 用户开启记忆功能。
2. 系统在新增心情或会话后提炼候选记忆。
3. 后端保存记忆摘要、标签、来源、置信度。
4. AI 回复时读取当前用户的有效记忆。
5. 用户可在设置页查看和删除记忆。

## 前端改动

- 设置页或个人页增加“AI 记忆”入口。
- 展示记忆列表、来源、更新时间、删除按钮。
- 增加开启/关闭记忆开关。

## 后端改动

- 新增记忆 Controller、Service、DTO、VO、Mapper。
- AI 回复前读取有效记忆并拼入 prompt。
- 记忆提炼失败不影响主业务。

## 数据库改动

- `mood_memory`：用户记忆表。
- 字段建议：`user_id`、`memory_type`、`summary`、`tags`、`source_type`、`source_id`、`confidence`、`status`。
- 索引：`user_id + status + update_time`。

## API 设计

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| GET | `/ai/memory/list` | 登录用户 | 查看我的记忆 |
| PUT | `/ai/memory/{id}/status` | 登录用户 | 启用或停用记忆 |
| DELETE | `/ai/memory/{id}` | 登录用户 | 删除记忆 |
| PUT | `/ai/memory/setting` | 登录用户 | 开启或关闭记忆 |

## 权限与安全

- 记忆属于高度隐私数据，只能本人访问。
- 用户必须能关闭和删除。
- 不保存医疗诊断式结论。
- 不把记忆用于社区公开展示。

## 异常处理

- 记忆不存在或不属于当前用户：返回无权限或不存在。
- AI 提炼失败：记录日志，不阻断心情保存。
- 关闭记忆后：AI 回复不再读取记忆。

## 验收标准

- 用户能看到自己的记忆列表。
- 用户能删除或停用记忆。
- 关闭记忆后，AI prompt 不再使用记忆。
- 越权读取失败。
