# 部署与运行说明

部署按 [上线运行手册](../../deploy/README.md) 与 [迁移核查单](../../deploy/MIGRATIONS.md) 执行，模板位于 `deploy/`（环境变量、systemd、Nginx、Redis）。实际连接信息与凭据由用户在终端管理，不写入仓库、交付文件或聊天。

## 部署形态

单台服务器：一个 Java 后端（只监听回环，唯一启用 worker），同机回环的 Python AI 服务与 Redis，Nginx 提供前端静态文件并把 `/api` 反向代理到 Java，内部路径对外返回 404。数据库为 MySQL 8.0。

## 两类发布

- **含数据库变更的完整发布**（如 2026-11-17 首次上线）：停旧应用 → 备份并恢复验证 → 逐份增量迁移 → Java（worker 关）→ Python → 同批前端与 Nginx → 冒烟 → 确认唯一 Java 后开启 worker → 观察。不得把含 DROP 的 `sql/xinyu.sql` 用于已有数据的库。
- **无迁移的标准发布**（如 2026-11-18 社区分页）：从已通过两层 CI 的提交构建 jar 与前端，上传到新的发布目录并核对 SHA-256，切换 Java 与前端、重启唯一 Java，只读冒烟与观察；旧发布目录保留，回退只需切回。

接口返回结构变化（如社区列表改为分页）时前后端必须同批切换，已打开的旧页面需要刷新。

## 安全与凭据

- `JWT_SECRET` 必须是独立随机值（至少 32 字节），缺失、过短或为旧固定值时拒绝启动。旧固定密钥已在公开 Git 历史中，**回退到 2026-11-17 之前的旧后端会重新暴露令牌伪造风险**，不能作为安全回退方案。
- Java 与 Python 的内部令牌一致且只在服务器生成；Redis 只监听回环并设密码。
