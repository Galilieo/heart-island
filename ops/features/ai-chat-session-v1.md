# AI 多轮对话模块 v1

状态：初版规划，未实现。

## 功能目标

在现有单次 AI 回复基础上，增加“会话”和“消息”概念，让用户可以围绕一次心情记录继续追问、补充背景、获得连续陪伴式回复。

## 用户场景

- 用户写完一条心情记录后，对 AI 回复继续追问。
- 用户进入“AI 陪伴”页面，查看最近会话并继续对话。
- 用户希望系统记住本轮对话上下文，但不需要永久记忆。

## 业务流程

1. 用户从心情详情或 AI 陪伴入口进入会话。
2. 前端创建或打开会话。
3. 用户发送消息。
4. 后端读取会话最近若干条消息，构造 prompt。
5. AI 返回回复，后端保存用户消息和 AI 消息。
6. 前端展示消息流。

## 前端改动

- 新增会话列表和聊天窗口。
- 心情详情页可进入相关会话。
- `src/api/` 新增会话接口封装。
- 需要处理发送中、AI 回复中、失败重试、空会话。

## 后端改动

- 新增会话 Controller、Service、DTO、VO、Mapper。
- 复用现有 AI API 调用能力。
- 保存用户消息、AI 消息、关联心情记录。
- 限制用户只能访问自己的会话。

## 数据库改动

- `ai_chat_session`：会话主表，记录用户、来源、标题、状态。
- `ai_chat_message`：消息表，记录会话、角色、内容、状态。
- 常用索引：`user_id + create_time`、`session_id + create_time`。

## API 设计

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| POST | `/ai/session/create` | 登录用户 | 创建会话 |
| GET | `/ai/session/page` | 登录用户 | 我的会话分页 |
| GET | `/ai/session/{id}/messages` | 登录用户 | 会话消息 |
| POST | `/ai/session/{id}/send` | 登录用户 | 发送消息并获取 AI 回复 |

## 权限与安全

- 会话必须属于当前用户。
- prompt 中不要拼接无关用户数据。
- 单条消息长度需要限制。
- v1 先不做公开分享。

## 异常处理

- 会话不存在或不属于当前用户：返回无权限或不存在。
- AI 失败：保存用户消息，AI 消息标记失败，前端给重试入口。
- 消息过长：直接参数错误。

## 验收标准

- 用户能创建会话并连续发送至少 3 轮消息。
- 刷新页面后历史消息仍可展示。
- 访问他人会话失败。
- AI 失败时页面不崩溃。
