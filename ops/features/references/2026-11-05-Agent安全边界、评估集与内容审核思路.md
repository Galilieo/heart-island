## 参考内容（简体转写）

- **安全边界**：这是情绪类产品，一定会遇到用户表达自伤或危机的情况。设计一层危机识别，碰到时不让 agent 自由发挥，而是引导用户找专业求助资源，并且把这套机制写清楚。这既是必要的，也是面试时很好讲的设计决策。
- **评估集**：准备几十条测试消息，分三类：该调工具的、不该调工具的、危机类的。检查工具选择是否正确、危机是否都被拦下。改 prompt 前后各跑一次，数据就出来了。

## 另一个可以考虑的方向

后台已经有帖子、回复的治理功能，可以做一个**内容审核 agent**：自动初筛社区内容，给出“建议隐藏或保留”和理由，最后由管理员确认。这属于 human-in-the-loop 的设计，风险比直接面对用户情绪低，而且很像真实公司会做的东西。如果你们担心陪伴型 agent 的责任问题，可以从这个入手。
